A paired result, not a leaderboard claim

The saved Kaggle session measured the baseline, then two optimized runs, then the baseline again. It used one T4 for a fixed 64-step LoRA workload based on Qwen2.5-1.5B-Instruct. End-to-end time includes setup, compilation, training, and saving the adapter.

What changed in the kernels

Output head and loss
Process the vocabulary in blocks instead of holding the full logits tensor in memory, while still computing loss and training metrics across the vocabulary.
Backward pass
Recompute MLP gate and up projections on supported paths rather than retaining wide activations.
Quantized projections
Share NF4 dequantization across compatible projections and group QKV operations without changing the stored quantization format.
Normalization and position
Reduce intermediate buffers, type casts, and some work on padding rows in supported RMSNorm and RoPE paths.

What the research ledger contains

Why the distinctions matter

  • Component checks: LoRA saved-state replay passed local comparisons, including CPU autograd cases. This did not establish GPU memory savings or whole-task speed.

  • Development comparisons: A 38.12 s training-command result was compared with a saved 38.49 s optimized reference, not a freshly paired baseline. It does not replace the 47.73 s paired result.

  • Negative results: The archive keeps failed admission checks, an NF4 parity failure, and partial runs. An observed peak from an unfinished job is not a full-run memory result.
